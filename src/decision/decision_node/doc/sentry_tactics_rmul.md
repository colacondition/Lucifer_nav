# 哨兵战术设计（中心占领 / 胜利点规则）

> **规则（已确认）**
> - 双方各 200 胜利点。占领中心**每秒**扣对方 1 点；**击杀敌方单位**扣对方 20 点。
> - 占领权归"**区域内先进入的一方**"。只有该方在区域内**完全清空**（全部被击杀或离开）后，
>   占领权才释放，对方进入即可占领。区域内还有他的队友，占领权仍归他们。
> - 占领区是**地图中心的一个正方形**，`patrol.csv` 的点全部在区域内。
> - 走位的点位按 **CSV 顺序**分两段：前段靠家（保守）、后段激进（见 §5.4）。
> - 死亡后 15s **原地复活**，进入**虚弱**：10s 无敌，但**无法占领/扣点**；需回家回血解除虚弱。
> - 总时长 300s；先把对方打到 0 者胜；时间到比剩余点数；点数相同**比总伤害**。
> - 哨兵是三个单位里热量 / 底盘 / 血量上限最高的。
>
> **协议依据**：RoboMaster 2026 通信协议 V2.0.0（20260626）。报文字段映射见 §9。

## 1. 记分账：硬通货是"占领秒数"

把一切折成同一个单位——**等效占领秒数**：

| 事件 | 等效占领秒数 |
|---|---|
| 占领中心 1 秒 | 1 |
| 击杀敌方单位 1 次 | 20 |
| 被击杀 1 次 | 20 + 我方失去占领能力的时长 |

**纯占领打光对方 200 点需要 200 秒**，全场 300 秒 ⇒ **占用率 66.7% 就锁定胜局。**
反过来：对方占用率超过 66.7%，我方必输。**这是整场比赛的唯一主线。**

### 1.1 一次死亡的代价（用实测地图数据估算）

| 项 | 值 | 来源 |
|---|---|---|
| 等待复活 | 15 s | 规则 |
| 无敌期（不能占） | 10 s（可覆盖部分赶路） | 规则 |
| 中心 ↔ 家 往返 | **12.92 m ≈ 8.6 s @1.5 m/s** | `center.csv` ↔ `home.csv` 实测单程 6.46 m |
| 回家回血 | T_heal（待实测） | — |
| 被击杀点罚 | 20 点 = 20 秒 | 规则 |

```
失去占领时长 ≈ 15 + 8.6 + T_heal − 10(无敌覆盖) ≈ 13.6 + T_heal
等效总代价   ≈ 20 + 13.6 + T_heal
若 T_heal = 10 s  ⇒  ≈ 44 秒 ≈ 全场的 15%
若 T_heal = 20 s  ⇒  ≈ 54 秒 ≈ 全场的 18%
```

**死 3 次 ≈ 丢掉半场比赛。而一次击杀只值 20 秒。**
⇒ **收益风险比约 1 : 2.2 ~ 2.7，为击杀冒险是亏的。**

## 2. 占领权的转移机制（本规则的核心）

```
区域内我方 > 0 且 敌方 = 0   →  我方占领
区域内敌方 > 0 且 我方 = 0   →  敌方占领
双方都 > 0                  →  归"先进入"的那一方（当前这一轮停留的先后）
双方都 = 0                  →  无人占领
```

三条由规则直接推出的结论，决定了全部战术：

**① 哨兵一个人离开区域，不一定丢占领——只要队友还在里面。**
⇒ 撤离代价是**条件性**的：

```
撤离代价 = 往返时间 + ( 区域内有我方队友 ? 0 : 白送占领权 + 重新夺回的成本 )
```

**② 夺回占领只能靠"把区域内敌人清空"，不是靠"我也进去"。**
敌人在里面时我进去 → 双方都在 → 占领权仍归他（他先进）。
⇒ 进入区域的唯一意义是**用火力把他打死或逼走** —— 本质是清场，不是占位（见 §5.1）。

**③ 哨兵是占领的承重墙。**
它最硬、血量上限最高、最不需要回家。队友（英雄/步兵）会比它先撑不住。
⇒ **队友回家时哨兵必须留；哨兵要回家时最好有队友接替。**
⇒ 哨兵是"**最后一个离开区域**"的单位。

### 2.1 **必须实现**：把 0x0101 的状态 3 消解成实际占领方

协议给的是 `bit 23-24`：`0 未被占领 / 1 被己方占领 / 2 被对方占领 / 3 被双方占领`。
**状态 3 不告诉你谁在扣点**——而按规则，只有"先进入"的那一方在扣。

消解办法只有一条：**看状态是从 1 变来的还是从 2 变来的**。

```
上一次稳定状态 = 1（我方） →  出现 3  ⇒  实际是我方在占
上一次稳定状态 = 2（敌方） →  出现 3  ⇒  实际是敌方在占
从 0 直接到 3（同时进入）  ⇒  需要退化处理：按"上一拍区域内我方是否有人"推断；
                             推断不出时按敌方处理（保守，不虚报自己得分）
```

这条逻辑必须实现，否则积分会错——**它同时也是"我方是否守住"的唯一判据**。
（cod_sentry 的 README 描述过这套判断，但它的代码把它压成了一个 bool，没有落地。）

### 2.2 1 Hz 的延迟约束

`0x0101` 固定 1 Hz 发送 ⇒ 占领状态**最多有 1 秒延迟**。

| 影响 | 量化 | 处置 |
|---|---|---|
| 占领积分误差 | ±1 秒 = ±1 点 | 可接受 |
| "离开区域后看状态"的反馈延迟 | 1.5 m/s × 1 s = **1.5 m** | 只做事后确认，不做实时边界控制 |
| 状态 3 的消解 | 需要连续两拍 | 用最小保持时长防抖（复用现有 `*_hold_sec` 思路） |

⇒ **不要把 1 Hz 的占领状态接进任何需要亚秒响应的环**（比如"贴边徘徊"）。

### 2.3 低延迟替代：`0x0209` bit 23 的中心增益点 RFID

`0x0209`（RFID 检测，常规链路）**bit 23 = 中心增益点（仅 RMUL 适用）**，
含义是"是否已检测到该增益点的 RFID 卡"——它是**机器人本地读卡、即时置位**，
没有 1 Hz 的采样延迟。

| 信号 | 语义 | 延迟 | 用途 |
|---|---|---|---|
| `0x0101` bit 23-24 | **谁在占领**（4 态） | 1 Hz | 积分、状态机分支 |
| `0x0209` bit 23 | **我是否物理压在中心点上** | 即时 | 「进入区域」是否完成的判定 |

**两个信号互补**：`0x0101` 回答"归谁"，`0x0209` 回答"我到了没"。
把「我进区域了没」的收敛判据接在 RFID 上，可以避免"到了还在等 1 秒确认"。

⚠️ **两个必须注意的点**：
1. **赛外恒 0**。协议注明"所有 RFID 卡仅在赛内生效。在赛外，即使检测到对应的 RFID 卡，
   对应值也为 0" ⇒ **这条信号无法在赛外/仿真里测试**，所有逻辑必须能在它为 0 时降级工作。
2. RFID 读卡范围**未必等于占领正方形**（正方形是规则判定的虚拟区域，RFID 是物理卡），
   两者可能有偏差 ⇒ **不能拿 RFID 当作占领判据**，只能当"接近中心"的辅助信号。

## 3. 六条硬纪律

这五条是从 §1 的账和 §2 的排他性直接推出来的，不随 `aggression` 变：

1. **占住区域是唯一主线，击杀是配菜。** 1 次击杀 = 20 秒占领；追击的边界就是
   "预期追击时间 < 20 秒"，而且要保证不离开区域。
2. **绝不为击杀冒险死亡。** 一次死亡 ≈ 2.2~2.7 次击杀。
3. **永不越出占领区**（实现上用 §5.4 的凸包保证，不靠调参）。
4. **虚弱期待中心是零收益**（不能占、不能扣点）⇒ 立刻回家；**10s 无敌是全场唯一的免费路权**。
5. **开局抢中心优先于一切。** "先进入的视为占领"，开局先手决定谁先开始每秒扣点。
6. **打伤害永远有保险价值**（平分比总伤害）⇒ **在区域内对射是双赢**：既占点又攒伤害。
   结论：哨兵不该躲，而该"**占着打**"。

## 4. 胜利点自己积分（**官方协议不给机器人发得分**）

### 4.1 能拿到什么、拿不到什么

| 量 | 常规链路（NUC 可访问） | 结论 |
|---|---|---|
| `T_our` 我方占领秒数 | `0x0101` bit23-24，1 Hz | ✅ 自己积分 |
| `T_them` 对方占领秒数 | 同上（需 §2.1 消解） | ✅ 自己积分 |
| `D_us` 我方被击杀次数 | 自身血量归零（`0x0201` 10 Hz） | ✅ 可检测 |
| `K_us` 我方击杀敌方次数 | **无**（协议不给对方机器人血量） | ❌ **算不出** |
| 双方总伤害差 | **`0x0003` 偏移 8，`int16 damage_difference`，3 Hz** | ✅ **直接可用** |
| 双方得分（胜利点） | **无**（只在图传链路的自定义客户端协议 `GameStatus.red_score/blue_score`） | ❌ 拿不到 |

**关键结论：**
- **`P_us` 可以自己算**：`P_us = 200 − T_them − 20 × D_us` ✅
- **`P_opp` 算不出**：缺 `K_us` ❌
- **但 `damage_difference` 是现成的**——正好是"平分比总伤害"的判据 ✅

### 4.2 由可算量推出的判定（都是喂给 §5.2 的 `aggression`，不是"模式切换"）

`P_opp ≤ 200 − T_our`（击杀只会让它更低），据此得到**单侧可判定**的几个量：

| 判定 | 条件 | 作用 |
|---|---|---|
| **已锁定胜局** | `P_us + T_our > 200 + R` | `aggression` 压到最低：**赢了别冒险** |
| **我方点数吃紧** | `P_us ≤ R` | `aggression` 压低 + 撤离阈值上移 |
| 占领时间缺口 | `need − R`（`need = 200 − T_our`） | 缺口越大 → `aggression` 越高 |
| 平分保险 | 可能平局且 `damage_difference < 0` | `aggression` 抬高：去堆伤害 |

推导：`Δ = P_us − P_opp ≥ P_us − (200 − T_our)`，所以 `P_us + T_our > 200 + R` ⇒ `Δ > R` ⇒ 已锁定。

⚠️ **`P_us ≤ R` 不改变"要占住"这个动作。** 早期的版本在这里写过
"必须阻止对方占领（哪怕自己也不占）"，那是错的 —— 由 §5.1 的排他性，
**我占住本身就是阻止对方扣分**，没有第二个动作可选。

**降级说明**：拿不到 `P_opp` 的代价是失去了"能否靠占领翻盘"的判定（只剩充分条件），
上表可用的四条**全部保住**。

### 4.3 想要完整 `Δ` 的话，唯一的路

`red_score` / `blue_score` 在**图传链路的自定义客户端协议**（`GameStatus`，5 Hz）。
要拿到它需要一个自定义客户端，再用 `CustomControl`（≤30 字节，75 Hz）
把得分转发给机器人。**这是一条真实存在但需要额外设备的路径**，不建议作为主线。

## 5. 战术结构：一个不变量 + 一个连续轴 + 一个例外

### 5.1 不变量：**占住区域**

由 §2 的排他性直接推出：**占领是我方与对方互斥的**。
对方要扣我们的分，他必须先占住；而我们占住的时候他占不住。

⇒ **「我占住」和「阻止对方占住」是同一个动作。** "防止被归零"的最优应对不是去干扰，
而就是占住。**所有局面的最优动作都是同一个：占点。**

所以状态机不该按"守 / 抢 / 清场"分成几个状态 —— 它们只是这个不变量在三种情形下的表现：

| 当前情形 | 不变量要求 | 表现 |
|---|---|---|
| 我方占领中 | 保持 | 留在区域内 |
| 无人占领 | 建立 | 进入区域（进去即成为"先进入者"） |
| 对方占领中 | 夺回 | 进入区域，**清场**（把他打死或逼走）——按 §2，单纯"我也进去"夺不回 |

**没有第四种情形。** 原来那套 `RUSH / CONTEST / HOLD / REGROUP` 全都可以并进这一条。

### 5.2 唯一真正的决策：`aggression ∈ [0, 1]`

既然动作恒为"占住"，**唯一可决策的就是占住时有多激进**：

| | 保守（aggression → 0） | 激进（aggression → 1） |
|---|---|---|
| 区域内站位 | 靠家一侧（退路短） | 靠中心 / 靠敌方一侧（更实、更易接战） |
| 区内换位 | 少动，只在被集火时换 | 主动换位找视角 |
| 接战尺度 | 占着打，不主动追 | 主动压制 |
| 撤离阈值 | 提前撤（血还多就走） | 延后撤（更愿意赌） |

**这一轴是连续的**，所以行为也是连续的："激进/防守"不是一个开关，而是站位、暴露、
换位意愿、撤离阈值一起平滑移动。**这同时修掉了原来的机械感** —— 机械感的来源正是
"离散状态跳变"，而不是缺状态。

**输入与方向**（系数是配置项，需要仿真里标定）：

| 输入 | 可算性 | 对 aggression 的作用 |
|---|---|---|
| 占领时间缺口 `need − R`（`need = 200 − T_our`） | ✅ 可算 | 缺口越大 → **越激进**（时间不够了要追） |
| 时间宽裕 `R − need` | ✅ | 越宽裕 → **越保守**（赢了别冒险） |
| 我方剩余点数 `P_us` 吃紧 | ✅ | 越接近 0 → **越保守**（别送最后那点血） |
| 自身血量比例 | ✅ | 越低 → **越保守** |
| 队友血量（越低的那一个） | ✅ | 越虚 → **越保守**（要留人守点） |
| 伤害差（平局保险） | ✅ | 只在"可能平局且伤害落后"时 → **越激进**（去堆伤害） |

⚠️ **不要用"对方血量"或"击杀数"驱动这一轴** —— 官方协议不给，算了也是假的（§4.1）。

### 5.3 唯一例外：无法以"占点状态"存活 → 回家

`aggression` 再低也仍然是"占住"。但有**两种情形占点本身没有意义或不可持续**，
这时才离开区域：

1. **虚弱期**：协议规定虚弱时不能占领、不能扣点 ⇒ 待在中心是**零收益**（§6）。
2. **低血到会死**：一次死亡 ≈ 44~54 秒等效代价（§1.1），远大于回家往返。

两者的动作相同：**回家恢复**。恢复完成后不变量重新生效（回区域）。

**撤离判据**：
```
撤离  ⟺  往返时间 + 夺回成本  <  死亡概率 × 50 秒
```
往返 ≈ 8.6 s + T_heal ⇒ **死亡概率超过约 25~30% 就该撤**。
无队友接替时，"夺回成本"要计入（我走了占领权就白送，回来还得清场）。

所以低血阈值要从现在的 30%（`low_threshold=120 / 400`）**上移**，并且随 `aggression` 移动：
激进时允许多扛一会儿，保守时提前撤。

### 5.4 活动范围：现成航点本来就都在区域内，不需要新建

占领区是**正方形**（凸集），且 `patrol.csv` 的点**全部在区域内**（已确认）
⇒ 正方形 ⊇ 这些点的**凸包**。

这条的性质是「**证明**」，不是「要建的东西」：

- **候选站位不用建** —— 现成的点就是候选集。
- **不用为「路径会不会出界」做任何处理** —— 正方形是凸的，两端都在里面，
  连直线段都在里面，所以任意两点之间怎么走都不会掉占领。
- 也**不需要知道正方形的确切边界或半径**，凸包性质已经兜住了。

**位置怎么选（已定稿）**：点池按 **CSV 顺序**分成两段 —— 前 `conservative_count` 个是
"靠家"的保守型，其余是激进型；每次触发按激进度**在两段之间按比例取点**
（`n_激进 = round(aggression × path_len)`），所以过渡期里一条路径会**同时含两种点**。
一条路径按池下标降序 = 激进点在前、保守点在后，路径本身就写成"从激进侧退到保守侧"。
**分段只看文件顺序，不做任何几何推断。**

**触发方式**：到达中心立刻触发第一次，之后走完一组换下一组。
原来 `pickRandomPath`（随机抽 3 个并打乱顺序）已删除。

**触发条件（最终版）**：一组走完 → 停 `group_gap_sec`（默认 4.5s）→ 再走下一组。
不用固定周期 —— 固定周期配 `path_len` 个点必然要么站着等、要么路径走不完被换掉
（点会被跳过后面的）。停顿从**走完那一刻**起算。见 `README.md` §4.3。

**"不停"靠执行器侧两处改动**（`README.md` §4.5）：action 新增 `stop_at_final`，
走位传 `false`（终点也按 `switch_distance` 切、全程不开接近段）；
executor 的 `switch_distance` 从 0.6 调到 0.3（原来比走位点间距还大，
机器人"刚开始走"就算到点）。

⚠️ 走位下发用 `TargetName::Patrol`，**不能**用 `WaitCenter` —— 后者是守点型目标，
而守点容差（0.35 m）远小于走位半径（1.58 m），会把车每 0.8s 拽回锚点一次。
见 `README.md` §6.1。

## 6. 虚弱期：10s 无敌是免费路权

虚弱 = 不能占 + 不能扣点 ⇒ **在中心毫无价值**。而 10s 无敌意味着这段时间不会被打死。

⇒ **复活后立刻（含无敌窗口）回家**，把二次死亡风险压到零。
这是全场唯一"被打也不亏"的赶路窗口，等价于免费获得 10 秒安全通行权。

唯一例外：只能靠伤害翻盘且虚弱不影响输出时，可用无敌期**当诱饵吸收弹药**。默认不开。

## 7. 对现有实现的影响

按 §5 的结构，**现有那套"每个子状态一个动作"的写法整个不成立**：动作恒为"占住"，
唯一的决策是 `aggression`。所以改动是**做减法**：

| 现状 | 问题 | 改法 |
|---|---|---|
| `CenterSubstate` = `Hold / Engage / Reposition` 三态 | 把"连续的一个轴"切成了离散三态 ⇒ **机械感的来源** | 收敛成 `aggression` 一个连续量 + "是否在区域内" |
| `CENTER.REPOSITION`：被打 → 随机 3 点跑掉 | **每次被打都离开区域**，可能白送占领权 | **整条删除**。区内换位由 `aggression` 决定，且永不越出凸包 |
| `CENTER.HOLD`：钉在锚点，偏出 0.35 m 才纠偏 | 静止 → 机械感 | 改成"到达中心自动走位、每 `interval_sec` 换一次位置" |
| `CENTER.ENGAGE` / `CombatConfig` / `combatAssessment()` | 整条链已随子状态一起删除（`shooter_heat` 也不再从协议里取） | **已删除**，见 §5.2 |
| 低血阈值 120/400 = 30%（硬编码） | 死亡代价远大于回家代价，阈值偏低 | 上移，并随 `aggression` 移动（§5.3） |
| `patrol.csv` 当随机池 | 随机抽 3 个 + 打乱顺序 → 抽搐 | **候选集与顺序都不变**（点本来就都在区域内）。只改用法：按 CSV 顺序分两段、`aggression` 选段、段内顺序推进；`pickRandomPath` 删除 |
| 无占领状态输入 | 无法判断该守还是该抢 | 协议层已完成（§8、§9） |

**净效果**：`decision_state_machine.cpp` 里 `tickCenter()` 那一整段交战子状态逻辑
（三个子状态 + 两个最小保持时长）可以缩成"算一个 `aggression`，按它选一段、段内按顺序取几个点"。

## 8. 数据（**实际只索取三个字段**）

协议前言的适用范围规则：**在两赛项间共用的条目对双方都适用；只适用于某一赛项的条目，
默认不适用于另一赛项。** 全文只显式标注了 3 处"仅 RMUL 适用"——其中 `0x0101` bit 23-24
（中心增益点）和 `0x0209` bit 23（中心增益点 RFID）正是我们要用的。

⇒ 前哨站、基地、飞镖、雷达、能量机关、中央/梯形高地、隧道、堡垒、工程机器人、空中机器人、
装配、金币经济、兑换、免费/立即复活——**全部是 RMUC 专属，3v3 里没有**。

### 8.1 数据清单（**实际落地的**）

上行只有一个帧（`'H','R'`，10 字节，净荷 5 字节），只有三个字段。
字段布局与给电控的接口说明见 `src/serial/doc/referee_frame.md`。

| 输入 | 报文来源 | 频率 | 用途 |
|---|---|---|---|
| 比赛类型 / 阶段 | `0x0001` byte 0（原样搬） | 1 Hz | 判比赛是否进行；校验是不是 3v3 |
| 剩余时间 | `0x0001` 偏移 1 | 1 Hz | **算中心走位的激进度** |
| **自身血量** | `0x0201` 偏移 2 | 10 Hz | 低血回家 |
| 自身血量上限 | **本地常量**（hero 350 / sentry 400 / infantry 300） | — | 不用转发，见 §8.2 |
| 自身位置 | 定位 + TF | — | 选走位点时算"离我多远" |

**为什么只要这三个**：走位不改变占领状态（§5.4），所以不需要中心占领状态；`aggression`
只由时间驱动，所以不需要得分、队友血量、伤害差。**这是简化决策层的直接结果。**

| 曾经列过、现在**没要**的 | 当时的用途 | 现在为什么不要 |
|---|---|---|
| 中心增益点占领状态 `0x0101` bit 23-24 | 解"该守还是该抢" | 走位不改变占领，不需要 |
| 队友血量 `0x0003` 偏移 0 / 4 | 队友虚弱 → 保守/让位 | 没有队友维度的决策了 |
| 双方总伤害差 `0x0003` 偏移 8 | 平分比总伤害的判据 | 同上 |
| 射击热量 `0x0202` 偏移 10 | 让 `ENGAGE` 判定复活 | `ENGAGE` 已不驱动动作 |
| 中心 RFID `0x0209` bit 23 | "我进区域了没"的低延迟判据 | 走位不需要 |
| 队友位置 `0x020B` | 撤离时是否有队友接替 | 没有撤离决策了 |
| 补给区占领 `0x0101` bit 2 | 回家路线是否安全 | 同上 |

**要加回来的时候**：往帧尾追加字段 + 改 `payload_len` 即可，不需要改帧型
（`payload_len` 机制就是为这个留的）。

### 8.2 血量上限：**本地定义是对的**（撤回上一版的建议）

上一版我建议转发 `0x0201` 的 `maximum_HP`，理由是 `0x020D` 有"哨兵成功远程兑换血量的次数"，
担心兑换抬高上限。**这条撤回**：

- 兑换（远程兑换血量/发弹量）、金币、免费复活、立即复活是一整套 RMUC 经济机制，
  **RMUL 3v3 没有** ⇒ 上限不会在局内变化 ⇒ **`hero 350 / sentry 400 / infantry 300`
  本地定义是安全的**，不用占协议字节。
- 唯一残留风险是"赛季换规则改上限"，而那是赛季前改一次配置的事，不是局内动态。

### 8.3 队友位置：协议里有，但本次没要

`0x020B` 是 **服务器→己方哨兵机器人**（40 字节，1 Hz），按 4 个槽位排布：
英雄、工程、步兵3、步兵4。**3v3 里没有工程机器人**，所以实际只需
英雄（偏移 0-7）+ 步兵（偏移 8-15）共 **16 字节**。

**本次没要** —— 它的用途是"撤离时判断是否有队友在区域内接替"，而简化后没有撤离决策了。
真要加回来时，代价是多转发 16 字节 + 一次坐标变换（下面的自动标定方案仍然成立）。

坐标也能自动标定：`0x0203` 给出**自身在场地系**的 `x,y`（float，m）和朝向（度，正北 0），
配合开机瞬间的 map 位姿，`map ← 场地` 是**三参数刚体变换**，可自动求解，不用人工测量。

**收益**：§2.1 的"撤离是否安全"能**事前判断**（队友还在不在区域内接替），
而不是离开后靠 1 Hz 的占领状态事后确认。

**已确认**：3v3 每队 3 个单位是 **hero 1 / infantry 3 / sentry 7**；
工程 2 与步兵 4 不在场 ⇒ `0x0003` 取偏移 0（英雄）和偏移 4（步兵），
`0x020B` 取偏移 0-7（英雄）和 8-15（步兵）。

**已确认**：`0x020D` 的哨兵姿态机制（进攻/防御/移动 + 强化/弱化）**3v3 不生效**
⇒ 整个 `0x020D` 报文对本设计无用，**不需要转发**。

**框架格式**（常规链路）：`SOF(0xA5)` + `data_length(2)` + `seq(1)` + `CRC8(1)` + `cmd_id(2)` + `data(n)` + `CRC16(2)`。
上行的 20 字节 `'H','R'` 是**我方与电控之间**的自定义帧，与裁判协议无关——裁判协议的解析在电控侧。

**两条链路的关键差别**：得分（`red_score`/`blue_score`）、击杀事件（`Event` id=1）、
复活状态（`RobotRespawnStatus`）、受伤统计（`RobotInjuryStat.killer_id`）
**都在图传链路的自定义客户端协议里，机器人的常规链路拿不到。**

**实际索取范围**：上表里只有 `0x0001`（byte 0 与偏移 1）和 `0x0201`（偏移 2）
被要求转发 —— 其余行都留着当"以后可能要"的索引，不是本次的需求。
